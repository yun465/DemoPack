# DemoPack 最终验收报告

日期：2026-09-16。结论：**Windows 本地首版验收通过，可以进入小范围真实项目试用。**
这不代表已经验证跨平台成熟度、真实用户采用或复用意愿。没有发布仓库、推送、联系用户或发帖。

## 本轮完成的改进

1. `validate`：录制前检查配置，错误指向具体字段，不需要先启动浏览器或安装媒体工具。
2. `verify`：核对必需文件、截图清单与 SHA-256，拒绝路径越界、文件缺失和内容变化。
3. `snippet --prefix`：生成适合仓库根 README 的相对链接，自动处理路径空格。
4. 预览支持自动分配空闲端口、端口冲突提示、缺少首页提示、可选系统浏览器打开；提供
   Windows 双击入口 `start-preview.cmd`，终端保持运行即提供预览服务。
5. 修复 320px 窄屏溢出、视频尾部范围请求，媒体改用流式传输。支持 HEAD 和单段 Range。
6. 长标题省略显示，保留步骤计数位置；完整标题仍在清单和教程中。
7. 关键截图必须是当前步骤操作完成后的帧，并写入 `screenshotAtMs`，防止使用上一阶段画面。
8. 采样间隔超过 500ms 或平均帧率低于目标的 60% 时，终端与清单给出质量提示。

这些补充服务于初次上手、导出可靠性和交付使用。没有扩大到编辑器、配音、云服务或账号系统。
后续功能取舍见 [产品成熟度判断](PRODUCT-READINESS.md)。

## 验收过程中发现的问题

- 隐藏同名文字会干扰等待：前一轮已复现并修复，本轮继续通过回归。
- 窄屏页面溢出、尾部 Range 请求返回200：本轮先观察到失败，再修复并通过原测试。
- 并行跑浏览器录制时曾出现约1.1秒采样停顿：[当时数据](evidence/concurrent-load-results.json)。
  已增加质量提示，并在无并行录制负载下重录最终样例。文件能解码不代表没有画面停顿。
- 新命令的最初测试失败于模块尚未存在；这是开发起点记录，不冒充独立缺陷复现证据。

## 未覆盖与后续门槛

- macOS、Linux 实际运行尚未验证。Linux CI 已配置，但没有远程执行证据。
- Windows 原生双击和系统默认浏览器的完整 GUI 行为不属于自动用例；CLI启动、端口和HTTP已实测。
- 取消测试覆盖 AbortSignal 对应的录制、MP4和GIF导出路径；没有模拟物理 Ctrl+C 按键、断电或强杀恢复。
- 高速动画、低性能机器、长时间录制、非 Chromium 浏览器、弹窗/iframe、多页身份流程没有验收。
- 没有五位真实维护者的首次上手、实际采用和再次使用数据。没有证据承诺 Star 数。

建议下一阶段先做跨平台和五个真实项目的试用。若主要阻力是写选择器，再考虑步骤编写辅助；若用户
已在用其他录制器，再考虑导入适配。现阶段不建议为“看起来完整”继续增加编辑器、配音和云功能。
